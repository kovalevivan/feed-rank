# Ограничение возраста постов для пересылки

## 📅 Дата: 12 октября 2025, 22:00 MSK

### 🎯 Цель

Не пересылать в Telegram новости (посты), которые были опубликованы более **48 часов назад**.

### ⚙️ Реализация

Добавлена проверка возраста поста в функцию `autoForwardViralPost` в `server/services/vk/index.js`.

### 📝 Логика работы

**Проверка возраста:**
```javascript
const postAge = Date.now() - new Date(post.publishedAt).getTime();
const maxAge = 48 * 60 * 60 * 1000; // 48 часов в миллисекундах

if (postAge > maxAge) {
  // Пост не пересылается
  console.log(`⏭️  Skipping viral post ${post.postId} - too old (${ageHours}h, limit: 48h)`);
  return { forwarded: 0, errors: 0, skipped: true, reason: 'too_old' };
}
```

**Используется поле `publishedAt`:**
- Заполняется из VK API: `new Date(post.date * 1000)`
- `post.date` - это Unix timestamp публикации поста ВКонтакте

### 🔄 Когда применяется

Проверка выполняется в **двух случаях**:

1. **Новый виральный пост** (строка 729 в `processSourcePosts`):
   ```javascript
   if (isViral) {
     viralCount++;
     const forwardResult = await autoForwardViralPost(newPost, source);
     // ...
   }
   ```

2. **Пост стал виральным** (строка 704 в `processSourcePosts`):
   ```javascript
   if (becameViral && existingPost.status === 'pending') {
     const forwardResult = await autoForwardViralPost(existingPost, source);
     // ...
   }
   ```

### 📊 Возвращаемые значения

Функция `autoForwardViralPost` теперь может возвращать:

```javascript
// Обычная пересылка
{ forwarded: 1, errors: 0 }

// Пост слишком старый
{ forwarded: 0, errors: 0, skipped: true, reason: 'too_old' }

// Нет маппингов
{ forwarded: 0, errors: 0 }
```

### 🎬 Примеры

**Сценарий 1: Свежий виральный пост**
```
Пост опубликован: 11 октября 2025, 20:00
Текущее время: 12 октября 2025, 10:00
Возраст поста: 14 часов
Результат: ✅ Пересылается
```

**Сценарий 2: Старый виральный пост**
```
Пост опубликован: 9 октября 2025, 08:00
Текущее время: 12 октября 2025, 10:00
Возраст поста: 74 часа
Результат: ⏭️  Пропускается (лог: "too old (74h, limit: 48h)")
```

**Сценарий 3: Пост ровно 48 часов**
```
Пост опубликован: 10 октября 2025, 10:00
Текущее время: 12 октября 2025, 10:00
Возраст поста: 48 часов
Результат: ✅ Пересылается (проверка: postAge > maxAge, 48h не больше 48h)
```

### 🪵 Логирование

При пропуске старого поста в логах backend-контейнера будет:

```
⏭️  Skipping viral post 12345 - too old (74h, limit: 48h)
```

Где:
- `12345` - ID поста ВКонтакте
- `74h` - фактический возраст поста в часах
- `48h` - установленный лимит

### ⚠️ Важные моменты

1. **Посты без `publishedAt` пересылаются:**
   - Если по какой-то причине `publishedAt` не заполнен, проверка пропускается
   - Это сделано для обратной совместимости

2. **Проверка выполняется ДО попыток пересылки:**
   - Не создаётся лишних запросов к Telegram API
   - Экономит ресурсы

3. **Порог виральности не зависит от возраста:**
   - Старые посты всё равно отмечаются как виральные в БД
   - Просто не пересылаются автоматически
   - Их можно пересылать вручную через UI

### 🎯 Преимущества

1. **Актуальность:** Только свежие новости попадают в каналы
2. **Релевантность:** Пользователи не видят устаревшую информацию
3. **Эффективность:** Не тратятся ресурсы на пересылку старых постов
4. **Логика:** 48 часов - разумный срок для новостей

### 🔧 Настройка

Для изменения лимита нужно отредактировать строку 24 в `server/services/vk/index.js`:

```javascript
const maxAge = 48 * 60 * 60 * 1000; // 48 часов
```

Примеры:
- 24 часа: `const maxAge = 24 * 60 * 60 * 1000;`
- 72 часа (3 дня): `const maxAge = 72 * 60 * 60 * 1000;`
- 1 неделя: `const maxAge = 7 * 24 * 60 * 60 * 1000;`

### 📈 Мониторинг

Для отслеживания пропущенных постов можно использовать:

```bash
# Логи пропущенных постов за последние 24 часа
docker-compose logs backend --since 24h | grep "too old"

# Подсчёт пропущенных постов
docker-compose logs backend --since 24h | grep -c "too old"
```

### 🧪 Тестирование

Для тестирования можно временно уменьшить лимит до 1 часа:

```javascript
const maxAge = 1 * 60 * 60 * 1000; // 1 час для теста
```

После чего запустить обработку источников и проверить логи.
