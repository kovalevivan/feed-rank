# Улучшение стратегии расчета порога (Threshold)

## Дата: October 12, 2025

## Проблема

**До изменений:**
- Порог рассчитывался на основе **фиксированного количества постов** (200 постов)
- Для групп, которые постят редко (например, 1-2 поста в день), это означало анализ постов за **3-6 месяцев**
- Старые посты накапливали просмотры за долгое время, что **завышало порог**
- Пример: группа постит 1 раз в день, 200 постов = ~6.5 месяцев истории

## Решение

**После изменений:**
- Порог рассчитывается на основе **временного окна** (30 дней по умолчанию)
- Анализируются только **свежие посты** из последних 30 дней
- Если постов мало (< 50), окно автоматически расширяется до 60 дней
- Максимум анализируется 200 постов

## Новая логика

### Функция `fetchPostsInTimeWindow`

```javascript
fetchPostsInTimeWindow(groupId, daysWindow = 30, minPosts = 50, maxPosts = 200)
```

**Параметры:**
- `daysWindow` - временное окно в днях (default: 30)
- `minPosts` - минимальное количество постов (default: 50)
- `maxPosts` - максимальное количество постов (default: 200)

**Алгоритм:**
1. Загружает посты пачками по 100 (VK API limit)
2. Фильтрует только посты из последних 30 дней
3. Пропускает закрепленные посты (pinned)
4. Останавливается при достижении maxPosts или при 10 подряд старых постах
5. Если найдено < minPosts, расширяет окно до 60 дней (рекурсивно)
6. Максимальное окно: 90 дней

### Примеры работы

#### Активная группа (10+ постов/день)
```
Окно: 30 дней
Найдено: 200+ постов
Используется: 200 постов (максимум)
Результат: ✅ Актуальный порог на основе свежих данных
```

#### Средняя активность (2-3 поста/день)
```
Окно: 30 дней
Найдено: 60-90 постов
Используется: все найденные посты
Результат: ✅ Адекватный порог на основе месячной истории
```

#### Низкая активность (< 2 постов/день)
```
Окно 30 дней: найдено 30 постов (< 50)
→ Автоматическое расширение до 60 дней
Окно 60 дней: найдено 60 постов
Используется: 60 постов
Результат: ✅ Порог на основе 2-месячной истории
```

#### Очень редкие посты (< 1 пост/день)
```
Окно 30 дней: найдено 20 постов
→ Расширение до 60 дней: найдено 40 постов
→ Расширение до 90 дней (max): найдено 80 постов
Используется: 80 постов
Результат: ✅ Максимально доступные данные
```

## Преимущества

### 1. Справедливый порог для всех типов групп
- ✅ Активные группы: свежие данные за месяц
- ✅ Средние группы: релевантная история
- ✅ Редкие группы: адаптивное окно без завышения

### 2. Избегание завышения порога
**До:**
```
Группа постит 1 раз в день
200 постов = 200 дней истории
Старые посты накопили просмотры → завышенный порог
```

**После:**
```
Группа постит 1 раз в день
30 дней = 30 постов
Окно расширяется до 60 дней = 60 постов
Все посты свежие → реалистичный порог
```

### 3. Автоматическая адаптация
- Система сама определяет оптимальное окно
- Не требует ручной настройки для каждой группы
- Учитывает индивидуальную частоту публикаций

## Технические детали

### Изменения в коде

**Файл:** `server/services/vk/index.js`

**Новая функция:**
- `fetchPostsInTimeWindow(groupId, daysWindow, minPosts, maxPosts)`

**Обновленная функция:**
- `updateSourceThreshold()` - теперь использует временное окно вместо фиксированного количества

**Также обновлено:**
- `fetchPosts()` - добавлен `filter: 'owner'` для исключения репостов и закрепленных постов

## Рекомендации

### Когда пересчитывать пороги

1. **После обновления кода** - пересчитать все группы один раз
2. **Регулярно** - автоматически раз в неделю (рекомендуется)
3. **При проблемах** - если порог кажется неадекватным для конкретной группы

### Мониторинг

Следите за:
- Количеством проанализированных постов (должно быть 50-200)
- Временным окном (30-90 дней)
- Группами с очень малым количеством постов (< 50)

## Ожидаемые результаты

После пересчета порогов:

1. **Редко постящие группы:**
   - Порог должен **снизиться**
   - Станет адекватным текущей активности

2. **Часто постящие группы:**
   - Порог останется примерно на том же уровне
   - Может незначительно измениться из-за свежести данных

3. **Общее улучшение:**
   - Более справедливое распределение порогов
   - Меньше "пропущенных" вирусных постов в редко постящих группах
   - Меньше "ложных срабатываний" из-за завышенных порогов
